# Orchestra

Рабочие инструменты для книги и документов ENOT. Пока здесь одна часть — читалка с версиями и замечаниями.

Ставить ничего не нужно: код работает на чистом Python 3.8 и старше, внешних библиотек нет.

## Что где лежит

```
Orchestra\
  config.json               настройки этой машины: путь к базе, порт
  config.example.json       образец настроек
  Запустить читалку.bat
  Проверить настройки.bat
  reader\                   код читалки
    book_reader.py          сервер
    theme.py                оформление и вёрстка
    structure.py            распознавание структуры текста
    notes.py                версии, замечания, история
    settings.py             чтение config.json
    nika.py                 сторона Ники: замечания, версии, правки
  docs\                     заметки по устройству
```

Сама база документов лежит отдельно — по умолчанию в папке `Yonote` на рабочем столе. Код и текст не смешиваются: Orchestra можно переносить и обновлять, не трогая книгу.

## Запуск

Двойной клик по `Запустить читалку.bat`, затем открыть в браузере http://localhost:8765

Если что-то не запустилось, сначала `Проверить настройки.bat` — он покажет, какой путь к базе взят и сколько документов найдено.

## Настройки

`config.json` в корне:

```json
{
 "base": "C:\\Users\\andrn\\Desktop\\Yonote",
 "port": 8765,
 "host": "127.0.0.1"
}
```

`base` — папка с документами. В Windows обратные слэши пишутся дважды.

`host` — кто может открыть читалку. `127.0.0.1` — только эта машина. `0.0.0.0` — вся локальная сеть, но по сети доступно только чтение: запись всегда разрешена лишь с той машины, где читалка запущена.

Путь к базе можно перекрыть, не трогая файл: параметром `--base "путь"` при запуске или переменной окружения `ORCHESTRA_BASE`.

## Перенос на другую машину

Скопировать папку `Orchestra` целиком, поправить `base` в `config.json` — и всё. Ничего в коде менять не надо, путь к базе нигде не прошит.

Если база лежит на другой машине, её нужно сделать видимой как папку: сетевой диск, общая папка или синхронизация. Читалка работает с обычными файлами и не знает, локальные они или сетевые.

## Как работать

Читаете последнюю версию главы. Выделяете текст — появляется плашка «Копировать» и «Цитата». «Цитата» открывает поле под абзацем, пишете замечание, сохраняете кликом по свободному месту или Ctrl+Enter. После сохранения страница остаётся на том же месте и подсвечивает вашу цитату.

Копию заранее создавать не нужно: замечания в текст не пишутся, они лежат отдельным файлом. Новую версию создаёт тот, кто правит текст.

Когда замечания готовы, жмёте **«отправить в работу»**. Читалка показывает список замечаний для подтверждения, потом создаёт задание и вызывает Нику. В правом нижнем углу появляется окно с полосой прогресса и лентой шагов — видно, что делается и сколько осталось. Заходить в Телеграм не нужно.

Если Hermes в этот момент не запущен, задание всё равно создаётся и ждёт: окно скажет об этом, а Ника возьмётся за работу, когда вы напишете ей в чате.

Прежняя версия становится эталоном и переходит в режим только для чтения. В новой версии правки Ники видны зелёными пометками со ссылкой на ваше замечание, а незакрытые замечания из прежней версии — приглушённо, с пометкой «ещё не отработано».

Кнопка со стрелкой в шапке показывает историю документа: все версии, замечания и правки с датами.

## Версии

Формат: `Глава 1. Лебедь, рак и щука_1.0.md`

Первая цифра — смысл, вторая — правка. Уточнения формулировок дают `_1.1`, `_1.2`. Переписанная подглава или новый смысловой блок — `_2.0`. Решение о том, младшая версия или старшая, принимает Ника и говорит об этом.

## Связь с Никой

В `config.json` два поля:

```json
"hermes_webhook": "http://127.0.0.1:8644/webhooks/nika-book",
"hermes_secret": "<тот же секрет, что в настройках Hermes>"
```

Запросы принимаются только с этой машины и только с верной подписью. Проверить связь:

```
python reader\hermes_link.py --test
```

Для работы нужен запущенный шлюз Hermes профиля `nika-redaktor`.

## Команды Ники

Из папки `reader`:

```
python nika.py todo                   все открытые замечания по базе
python nika.py show <файл>            замечания к документу с контекстом
python nika.py newver <файл>          создать следующую версию
python nika.py mark <файл> --frag ...  пометить правку
python nika.py hist <файл>            история документа
python nika.py diff <файл1> <файл2>   что изменилось между версиями
```
