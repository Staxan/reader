# Orchestra Reader

Рабочее место для длинных документов: чтение в книжной вёрстке, замечания
цитатой, версии — и агент, который берёт замечания в работу.

Ставить ничего не нужно: чистый Python 3.8+, внешних библиотек нет.

## Что умеет

- читать документы базы в книжной вёрстке, с картой главы и прогрессом;
- ставить замечания выделением текста, не трогая сам документ;
- вести версии: `_1.0`, `_1.1`, `_2.0` — прежняя всегда только для чтения;
- отправлять замечания агенту одной кнопкой и показывать ход работы;
- держать несколько агентов и привязывать их к документам и коллекциям;
- выгружать документы в ENOT (Yonote).

## Установка

```bash
git clone https://github.com/Staxan/reader.git Orchestra
cd Orchestra
cp config.example.json config.json
cp .env.example .env
```

В `config.json` укажите `base` — папку с документами. Дальше:

```
Запустить читалку.bat            (Windows)
python3 reader/book_reader.py    (WSL, Linux, macOS)
```

Открыть `http://localhost:8765`. Если что-то не так — `Проверить настройки.bat`
покажет, какой путь взят и сколько документов найдено.

## Настройки

`config.json` в корне:

```json
{
 "base": "C:\\Users\\andrn\\Desktop\\Yonote",
 "port": 8765,
 "host": "127.0.0.1",
 "yonote_url": "https://anewera.yonote.ru",
 "write_allow": [],
 "direct_bind": "auto"
}
```

`base` — папка с документами. В Windows обратные слэши пишутся дважды. Путь
можно перекрыть параметром `--base` или переменной `ORCHESTRA_BASE`.

`host` — кто может открыть читалку. `127.0.0.1` — только эта машина,
`0.0.0.0` — вся локальная сеть.

`write_allow` — кому разрешено писать замечания по сети: маски вида
`192.168.1.*`. Своя машина разрешена всегда. Без этого списка по сети доступно
только чтение.

`direct_bind` — с какого адреса выходить наружу. Нужно, когда на машине поднят
VPN-туннель, а сервер документов принимает только адреса своей страны:
`auto` — читалка сама подберёт рабочий адрес, `''` — как обычно, или точный
адрес адаптера.

## Секреты

Ключи и секреты живут в `.env` в корне, а не в конфигах. В `config.json` и
`agents.json` лежат только ссылки:

```json
"secret": "env:AGENT_SECRET_NIKA"
```

`.env` в репозиторий не попадает. Образец — `.env.example`.

## Агенты

Читалка сама находит агентов Hermes на машине: читает `~/.hermes/profiles/*`
и показывает, у кого связь настроена, а у кого нет. Страница «Агенты» —
значок ☼ в шапке.

- **готов** — можно подключить одной кнопкой, адрес и секрет читаются сами;
- **найден, связь не настроена** — кнопка покажет, что дописать в конфиг
  агента и какой командой перезапустить его шлюз;
- **добавить вручную** — если агент на другой машине или это не Hermes.

Реестр лежит в `agents.json`. Формат — в `agents.example.json`.

### Кто отвечает за документ

Агент привязывается к документу или к целой коллекции: три точки в дереве →
«привязать агента». Кнопка «отправить в работу» дальше ничего не спрашивает,
она отправляет тому, кто привязан.

Привязка ищется снизу вверх:

```
версия -> семья версий -> коллекция -> папки выше -> агент по умолчанию
```

Поэтому новый документ внутри коллекции подхватывает её агента сам, а новая
версия наследует агента главы.

## Как работать

Читаете последнюю версию. Выделяете текст — появляется плашка «Копировать» и
«Цитата». «Цитата» открывает поле под абзацем: пишете замечание, сохраняете
кликом по свободному месту или Ctrl+Enter.

Копию делать не нужно: замечания в текст не пишутся, они лежат отдельным
файлом. Новую версию создаёт тот, кто правит текст.

Когда замечания готовы — **«отправить в работу»**. В правом нижнем углу
появится окно с полосой прогресса и лентой шагов.

В новой версии правки агента видны зелёными пометками со ссылкой на ваше
замечание, а незакрытые замечания из прежней версии — приглушённо, с пометкой
«ещё не отработано».

Стрелки в шапке: история документа, агенты, выгрузка в ENOT. Стрелки у правого
края — в начало и в конец главы (Home и End). Карта главы всплывает, когда
подводите курсор к правому краю.

## Версии

Формат: `Глава 1. Лебедь, рак и щука_1.0.md`

Первая цифра — смысл, вторая — правка. Уточнения формулировок дают `_1.1`,
`_1.2`. Переписанная подглава или новый смысловой блок — `_2.0`.

Как только создана следующая версия, прежняя становится эталоном и переходит в
режим только для чтения.

## Выгрузка в ENOT

Значок ↑E в шапке. Поток в одну сторону: **файлы → ENOT**. Версии в базе
неизменяемы, а документ в ENOT правится в браузере, поэтому обратная выгрузка
приводила бы к конфликтам. Файлы — источник правды, ENOT — витрина.

Страница выгрузки показывает, что изменилось после прошлой отправки. Сравнение
идёт по отпечатку текста в `front-matter`, без обращения к сети.

Нужен `YONOTE_API_KEY` в `.env`.

## Команды для агента

Из папки `reader`:

```
python nika.py todo                   все открытые замечания по базе
python nika.py queue                  активные задания
python nika.py show <файл>            замечания с контекстом абзаца
python nika.py newver <файл>          создать следующую версию
python nika.py mark <файл> --frag ... пометить правку
python nika.py hist <файл>            история документа
python nika.py diff <файл1> <файл2>   что изменилось между версиями
```

У `mark` и `newver` есть `--author`. Без него автор берётся из привязки
документа к агенту.

## Что где лежит

```
Orchestra/
  config.json               настройки этой машины (в репозиторий не идёт)
  agents.json               реестр агентов (в репозиторий не идёт)
  .env                      ключи и секреты (в репозиторий не идёт)
  Запустить читалку.bat
  reader/
    book_reader.py          сервер и страницы
    theme.py                оформление и вёрстка
    structure.py            распознавание структуры текста
    notes.py                версии, замечания, история
    jobs.py                 задания и ход выполнения
    binding.py              кто отвечает за документ
    netpath.py              выход мимо туннеля VPN
    sync_yonote.py          выгрузка в ENOT
    settings.py             config.json и .env
    nika.py                 сторона агента
    agents/
      registry.py           реестр
      discover.py           поиск профилей Hermes
      hermes.py             связь через webhook
      cli.py                каркас под Codex, OpenCode
  docs/
    plan-reader.md          что делается сейчас
    plan-studio.md          куда это растёт дальше
```

База документов внутри Orchestra не хранится. Код и текст не смешиваются:
читалку можно обновлять, не трогая книгу.

## Перенос на другую машину

Скопировать папку, поправить `base` в `config.json`, заполнить `.env`. В коде
менять нечего: путей там не прошито.
