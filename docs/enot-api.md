# ENOT (Yonote) API: что проверено опытом

Дата опытов: 4 сентября 2026. Всё ниже — результаты живых запросов, а не чтение
документации. Пробные коллекции и документы после опытов удалены.

## Как ходить

RPC-стиль, база `https://app.yonote.ru/api`, каждый метод — свой POST-путь.
Ключ в заголовке `Authorization: Bearer <YONOTE_API_KEY>`.

Методов в спецификации 102. Полезные для читалки:

```
collections.create   collections.update   collections.delete
collections.info     collections.list     collections.export
documents.create     documents.update     documents.info
documents.list       documents.move       documents.archive
documents.import     documents.export     documents.copy
```

## Главное: create сохраняет разметку, update — нет

Один и тот же markdown, записанный двумя способами, читается назад по-разному:

| способ | решётки | жирный | списки | переводы строк |
|---|---|---|---|---|
| `documents.create` | 3 | есть | есть | все |
| `documents.update` | 0 | нет | нет | остались |

Пробовала `update` с `append: false`, с `title`, с `done` — результат тот же:
разметка срезается. Это поведение метода, обойти параметрами не удалось.

**Следствие для читалки: обновлять документ нельзя. Нужна замена** — создать
новый документ с тем же заголовком и родителем, старый отправить в
`documents.archive`.

Проверено: после замены разметка полная, в папке остаётся один документ,
порядок не ломается.

**Цена замены:** у документа меняется `urlId`. Прямая ссылка на прежний
документ перестаёт работать. Для книги терпимо — ссылки берутся из
front-matter и обновляются вместе с ним. Ссылки, выданные вручную, умрут.

## Что ещё пробовала для форматирования

- **HTML в поле `text`** — принимается как есть, но не преобразуется: теги
  остаются текстом в документе. Не годится.
- **Поле `data`** (внутреннее представление, ProseMirror) — запись проходит,
  но `documents.info` возвращает пустой `text`. Не годится без разбора формата.
- **`documents.import` файлом .md** — работает, разметка почти цела, но
  съедается первый заголовок. Годится как запасной путь, не как основной.

## Коллекции

Создавать можно. Проверено полным кругом: `collections.create` →
`collections.info` → `documents.create` внутрь → `collections.delete`.

`collections.list` отдаёт коллекции, но **без имён** — имя приходит только из
`collections.info` по каждой отдельно.

## Пустые документы

Если у файла нет текста (у нас это `_index.md` — папка-заголовок), выгрузка
затирает содержимое документа в ENOT. Проверено на главе 1: документ стал
пустым. Такие файлы выгружать нельзя, для них в читалке отдельное состояние
`empty`.

## Ссылки

`[текст](url)` ENOT срезает до анкера — адрес пропадает. Прямые URL и метки
сносок `[N]` сохраняет. Поэтому markdown-ссылки перед выгрузкой разворачиваются
в «подпись: адрес».

## Сеть

ENOT стоит на российском сервере и отбивает зарубежные адреса: соединение
рвётся на TLS-рукопожатии, выглядит как недоступность сервера.

Проверено на живом соединении:

```
без привязки сокета:            FAIL TimeoutError (handshake)  12.0 с
привязка к 192.168.1.140:       OK   HTTP/1.1 200 OK            0.2 с
```

Решение в `netpath.py`: привязка исходящего сокета к домашнему адресу. VPN при
этом остаётся включённым. Работает со стороны Windows, где этот адрес
существует; из WSL — нет, там трафик всё равно уходит через хост в туннель.

## Синхронизации нет и не планируется

Поток один: файлы → ENOT. Версии в базе неизменяемы, а документ в ENOT
правится в браузере в любой момент. Двусторонний обмен на таких правилах даёт
конфликты, которые руками не разобрать. Файлы — источник правды, ENOT — витрина.
